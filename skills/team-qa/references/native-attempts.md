# Native worker attempts

Native Team QA workers remain single-turn (`max_turns: 1`). An executor-GUI dispatch must name a `--case-id` from the signed tracked scope and the current verified continuation's next actionable case. Each case has a cap of three native dispatches, including an unassigned legacy primary conservatively counted against every case; the run also has a finite ceiling of signed case count times three dispatches. Planning roles retain a three-attempt role cap. A retry is a new dispatch under the same run, round, approved roster, target and plan; it has a new task identity, native session, intent, evidence and attestation. Do not edit prior intent, evidence, attestation or closure receipts. Renaming a task or changing board commentary never resets a case's dispatch count.

Planning-role attestations are accepted before PLAN and before a document lock exists. A GUI retry still requires the locked tracked scope to determine its cap; an absent or empty GUI retry directory must not block Test Manager or Analyst intake.

Capture native preparation as one complete tool result per `functions.exec`. Set a sufficient command wait (for example `yield_time_ms: 30000`); if it yields a session, collect its terminal result in a separate invocation. Do not combine that result with another tool output: the original prepare receipt must have one unambiguous successful payload before spawn.

After a successful attempt, `roster prepare-native` creates the next immutable attempt intent only after the prior attempt's attestation validates. The CLI retry form supplies both retry identity flags and the case binding, for example: `node scripts/roster.mjs prepare-native --run-dir "$RUN_DIR" --role executor_gui --prompt "$RETRY_PROMPT" --facts "$FACTS" --gui-policy "$GUI_POLICY" --case-id CART001 --attempt-id retry_cart001_0002 --attempt-seq 2`. Use a fresh ID and the exact next sequence; the dispatcher rejects a mismatched sequence, reused task identity, non-actionable case, or exhausted case budget. `roster attest-native` binds successful execution evidence. If a worker ended in a parser-authenticated terminal execution failure or verified timeout, `roster close-native` can record a typed closure receipt from the original native prepare, parent and child sources; this remains ungraded and permits bounded retry. It cannot close malformed provenance, an unverified failure, an active worker, or an arbitrary parser rejection. A missing source needed to authenticate terminal state remains blocked.

The legacy first attestation remains at `role-bindings/<role>.json`. Retries use `role-bindings/<role>/attempt-N.json` and bind the previous attestation or closure hash plus previous intent hash. Consumers should select the exact proof by `attestation_path`, `attestation_sha256` or `dispatch_attempt_id`; omission continues to resolve the legacy first attestation for compatibility. A new worker turn does not change the roster approval or count as new human approval.

Attempt closure, an evidence record, a continuation decision, or a published board is not a graded result. Preserve `PASS`, `FAIL`, `BLOCKED`, `NOT RUN`, `DEFERRED`, `PARTIAL` and `UNGRADED` distinctions, and use only the strict `COMPLETE` gate to complete a run.
