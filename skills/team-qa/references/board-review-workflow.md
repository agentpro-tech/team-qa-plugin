# Authenticated board quality workflow

Use this before delivering a Page, Notion projection or local board. Quality is separate from product Function/UI results. A quality failure keeps the board in draft and does not stop independent authorized test cases.

1. Edit the canonical revision and run `node scripts/board-quality.mjs inspect --file <canonical.json>`. Correct the listed fields. The legacy canonical validator remains available for working drafts.
2. Run `node scripts/board-quality.mjs recipe --file <canonical.json> --out-dir <new-directory> --parent-source <original-parent-jsonl> --author-source <same-parent-jsonl> --task-name <unique-name> --model <available-native-model> --effort <supported-effort>`. The parent takes responsibility for the frozen canonical snapshot; do not nominate an unrelated session as its author.
3. Execute the returned `functions.exec` code exactly, with no wrapper or additional calls. This invokes the pinned preparer and emits the intent hash. Dispatch the returned `spawn` object unchanged with native `collaboration.spawn_agent`. The fresh reviewer has no shared history, reads only the locked packet and facts, and returns one JSON result. It cannot authorize QA execution or change product verdicts.
   Claude Code root: `recipe` returns a shell command instead; run it with Bash exactly, then run the returned `dispatch_command` exactly. It starts one isolated, tool-less `claude -p` reviewer and prints the reviewer transcript as `child=`. Details in [Claude Code as root](claude-host.md).
4. After that child completes, run `node scripts/board-quality.mjs attest --intent <intent.json> --child-source <original-child-jsonl> --out <new-review-receipt.json>`. Attestation checks the exact preparation call, current protocol, provider source, original parent/child transcript, one-turn trajectory, complete case/defect coverage and all five review criteria. Missing or invalid proof is UNGRADED. A FAIL/UNGRADED review is preserved as evidence and cannot authorize delivery.
5. Pass the authenticated receipt as `--quality-review` to `teamqa board prepare`, `render` or Notion `sync --mode push`. The gate regenerates the projection and seals exact canonical, payload, rule and review hashes. `board open`, Page comparison and COMPLETE verify it again. Edits require a new review; keep previous revisions and receipts rather than overwriting them.

The review facts include source identities, linked requirements, all case/defect action prose, findings and captions. Opaque raw logs are not presented as prose. If the available source does not support a conclusion, the reviewer must FAIL or mark UNGRADED rather than assume missing content. Review improves detection; it does not guarantee every sentence is true or substitute for product testing.

For a registered run, lock `board_quality` to `<payload-or-html>.quality.json` and `board_payload` for a remote export, or `board_render` for local HTML. COMPLETE additionally requires the independent final readback. These publication artifacts can remain stale while independent execution continues, but cannot pass completion.

Registered direct Page creation uses `write-request --file <canonical> --payload <sealed-export> --destination <destination.json> --out <new-request.json>` and locks that request as `board_write`. The hook admits only its exact connector input after revalidating quality. Direct Page edits/visualizations and direct Notion writes have no verified projection adapter and are denied; use the gated Notion push adapter or prepare a new Page revision. This is a registered tool-path check, not an operating-system sandbox or a Production grant. Native enforcement also requires the user to trust the exact project hook definition in Codex.

Doc-Colab delivery pins the generator and template to its local canonical Git source receipt. Set `DOC_COLAB_SKILL_ROOT` and `TEAMQA_DOC_COLAB_SCRIPT` to the same verified candidate when rehearsing an isolated upgrade. Older templates that omit `defectSummary.handoff` cannot deliver an action board.

Keep repair attempts bounded. On the same failure twice, diagnose from the returned fields and reviewer anchors before changing the board; after three evidenced repair rounds, report the blocked delivery and recovery condition while continuing independent work.

An unattended run (`TEAMQA_RUN_MODE=unattended` on its approved roster) records that blocked delivery instead of asking: `teamqa board deliver-blocked --run <id> --reviews <r1,r2,r3>` re-authenticates the FAIL/UNGRADED review receipts (the last one of the locked canonical board) and writes `control/board-delivery.json`. The board is then neither delivered nor published; COMPLETE accepts the record in place of the publication artifacts, the report lists the open review points and the Team QA receipt carries `board_delivery: "blocked"`. An interactive run keeps asking the user.
